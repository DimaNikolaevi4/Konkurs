## 4. ЕСКД и ГОСТ — замечания

> ЕСКД (ГОСТ 2.105, 2.316, 2.104) распространяется на конструкторские документы; статья конференции к ним не относится, поэтому рамка и основная надпись по ГОСТ 2.104 не требуются. Ниже — только те нормы ЕСКД и ГОСТ 7.32/7.0.100, которые применимы к текстовому научному документу.

### 4.1. Исправлено: курсив в подписи рисунка (файл 1)
Подпись «Рисунок 1 — Принципиальная электрическая схема…» была набрана курсивом. По ГОСТ 2.105 и ГОСТ 7.32 подпись под рисунком набирают без выделения, по центру, с точкой только в конце поясняющего текста (в односоставной подписи точка не ставится). Курсив снят — теперь оба файла оформлены одинаково.

### 4.2. Требует правки: нет ссылки на рисунок 1 в тексте (файл 2)
По ГОСТ 2.105 п. 4.3.1 и ГОСТ 7.32 на каждый рисунок должна быть ссылка в тексте до самого рисунка. В статье про ИИ-тьютора есть только подпись, ссылки «…приведена на рисунке 1» нет.
Готовая вставка (в конец абзаца о LoRA-адаптации, перед рисунком):
> Структура интеллектуального тьютора приведена на рисунке 1.

В файле 1 ссылка есть — «…приведена на рисунке 1» в абзаце «Основная часть». ✅

### 4.3. Требует правки: не расшифрованы сокращения (файл 2)
По ГОСТ 2.316 и ГОСТ 7.32 все вводимые сокращения расшифровывают при первом упоминании либо выносят в перечень сокращений. Расшифровано только LLM — «Большие языковые модели (LLM)». Без расшифровки: **ИИ** (первое упоминание — «генеративного ИИ»), **API**, **GPU**, **CUDA**, **JSONL**, **PEFT**, **LoRA / QLoRA**, **LTS**.

Минимальный вариант правки (первое упоминание в скобках):
- «облачных сервисов генеративного ИИ (искусственного интеллекта)»;
- «внешних API (программных интерфейсов)»;
- «методом LoRA / QLoRA (низкоранговая адаптация)»;
- «в формате JSONL (построчный JSON)»;
- «сервер с GPU (графическим процессором), Ubuntu Server 22.04 LTS (долгосрочная поддержка), Docker, CUDA 12.x»;
- «библиотеки PyTorch, Transformers, PEFT (эффективная тонкая настройка)».

### 4.4. Отклонение от требований конференции: листинг кода 9 пт (файл 2)
Фрагмент программы набран 9 пт, тогда как требование — Times New Roman 10. Кроме того, по ЕСКД программный код приводят как рисунок или в приложении, с подписью; сейчас это просто абзацы без подписи.
Варианты: (а) поднять до 10 пт — объём остаётся 2 страницы, но нужно проверить переносы строк; (б) оформить как «Листинг 1 — Фрагмент программы (класс IntelligentTutor, файл tutor.py)» с подписью и одинарным интервалом. Рекомендую (б) — тогда 9 пт допустимы как оформление листинга, а не как основной текст.

### 4.5. Список литературы (файл 2)
- Источники **[5] Moodle Web Services API** и **[6] ТЗ Бардакова Д. Н.** в тексте не упоминаются. По ГОСТ 7.32 каждый источник списка должен иметь ссылку в тексте: либо сослаться на них (например, [5] — при описании интеграции с Moodle, [6] — при описании требований к системе), либо убрать.
- Стиль описаний различается между файлами: файл 1 — ГОСТ 7.1-2003 («Кулагин А. В. … / А. В. Кулагин»), файл 2 — ГОСТ 7.0.100-2018 («Vaswani, A. … / A. Vaswani, N. Shazeer»). Для единообразия стоит выбрать один стиль, лучше 7.0.100-2018.
- Источник [2] (Vaswani) дан только URL без года и объёма; для arXiv допустимо, но лучше добавить «— 2017. — 11 p.».
